# 서울 사고위험 길안내 (Flask + 카카오맵)

## 1. 노트북에서 실행 (로컬)

```bash
cd road-risk-layer
pip install flask lightgbm pandas numpy requests pyproj
dvc pull                      # model/results, data/service_tables 받기
python web/app.py             # → http://localhost:5000
```

`road-risk-layer/.env` 에 키 5개 (이 파일은 git에 안 올라감):

| 이름 | 어디서 | 쓰는 곳 |
|---|---|---|
| `KAKAO_REST_KEY` | 카카오 디벨로퍼스 앱 → 플랫폼 키 → REST API 키 | 경로 찾기 (카카오모빌리티 길찾기) |
| `KAKAO_JS_KEY` | **카카오맵이 켜진 앱** → JavaScript 키 | 지도 화면 |
| `KAKAO_MAP_REST_KEY` | **카카오맵이 켜진 앱** → REST API 키 | 장소 검색 (카카오 로컬) |
| `SEOUL_API_KEY` | 서울 열린데이터광장 → 일반 인증키 | 실시간 도로 속도 |

- 카카오맵(지도·장소 검색)은 앱의 **제품 설정 → 카카오맵 → 사용 설정 ON** 이 필요해요.
  무료 쿼터는 계정에서 **처음 켠 앱 하나**만 받아요. 그래서 지도·검색 키는 '빈집을 잇다' 앱 키를 써요.
- JavaScript 키 → **JavaScript SDK 도메인**에 `http://localhost:5000`, `http://127.0.0.1:5000` 등록 (등록돼 있음).
- 첫 위험 지도는 서울 전체 실시간 속도를 받느라 20~30초 걸려요 (그 뒤 10분은 저장값 사용).
- 내 위치(GPS)는 `localhost` 또는 `https` 주소에서만 돼요.

## 2. 화면 기능 (웹기능 체크리스트 결정 반영)

| 번호 | 기능 | 어디에 |
|---|---|---|
| 1 | 출발·도착 → 경로 최대 3개, 경로마다 위험 등급·소요시간을 지도 위 라벨로 | 왼쪽 패널 + 지도 |
| 2 | 장소·주소 검색, 📍 내 위치(GPS) | 출발/도착 입력칸 |
| 3 | 시간 슬라이더 (지금 ~ 72시간 뒤) | 2. 출발 시각 |
| 4 | 날씨: 자동(Open-Meteo) / 맑음·비·눈 직접 선택 | 날씨 |
| 5 | 막힘 정도: **실시간**(서울시 도로 속도) 또는 원활·평소·조금 막힘·많이 막힘 직접 선택 | 막힘 |
| 6 | 위험 지도, 칸 클릭 → 이유 카드, 위험 TOP10 칸, 경로 경고(⚠ 높음 구간) | 지도·패널 |
| 7·9 | 등급만 표시: 높음 빨강 / 보통 노랑 / 낮음 색 없음 | 지도 |
| 8 | 낮음 칸 클릭 → "비교적 안전해요" | 이유 카드 |
| 10 | 안내 문구 (과거 기록 기반 참고 정보) | 패널 아래 |
| + | **경로 안내 (네비게이션)**: 경로 카드의 "▶ 경로 안내 시작" | 지도 위 안내판 |

### 경로 안내 (네비게이션) 동작
- 카카오 길찾기 응답의 **안내 지점**(우회전·직진·톨게이트·도착 등)을 경로 선 위 위치로 바꿔 두고,
  차 위치에서 다음 안내 지점까지 남은 거리를 계속 계산해요.
- 화면 위: 다음 안내 (아이콘 + 남은 거리 + "남산3호터널 방면으로 우회전"), 위험 구간 띠
- 화면 아래: 남은 거리·시간, 도착 예정 시각, 속도, 모드, 배속, 일시정지, 음성 켜기/끄기, 안내 종료
- 음성(브라우저 한국어 음성): 안내 지점 500m 앞 / 150m 앞, 위험 '높음' 칸 300m 앞
  ("300미터 앞, 사고 위험이 높은 구간이에요. 최근 3년간 사고가 많았던 곳이에요"), 도착
- 모드
  - **주행 시뮬레이션**: 경로 평균 속도로 차가 자동으로 움직임 (1배·5배·20배). 노트북 발표용
  - **내 위치(GPS)**: 휴대폰 위치를 경로에 붙여서 안내. 경로에서 60m 넘게 3번 벗어나면 다시 경로를 찾아요 (재탐색)
- 안내 중에는 위험 지도 색을 옅게 해서 경로가 잘 보이게 해요.

### 단속카메라
- 원자료: 공공데이터포털 **전국무인교통단속카메라표준데이터** (2026-10 기준) → 서울 4,491대만 `web/data/cameras_seoul.csv`
  (`data_raw/camera/cameras_std.csv` 원본, 받는 코드 `data_raw/poi/get_std.py 15028200`)
- 종류: 과속 613 · 신호 1,854 · 구간단속 시작/끝 각 45 · 주정차 1,934 (단속구분 코드는 팀 camera.py 와 같은 방식으로 풀이)
- 경로 선에서 **25m 안**의 카메라를 그 경로의 카메라로 봄 (반대 차로 카메라가 같이 잡힐 수 있음)
- 경로 카드: "📷 과속 1 · 신호 5", 지도: 📷+제한속도 표시 (주정차는 📷P, 지도에만)
- 길안내 중: 500m 안이면 화면에 제한속도 원 + "280m 앞 신호 단속 카메라", 300m 앞에서 음성
  ("300미터 앞, 과속 단속 카메라가 있어요. 제한속도 50킬로미터입니다.")

### 어린이보호구역
- 원자료: 공공데이터포털 **전국어린이보호구역표준데이터** → 서울 1,601곳 `web/data/child_zones_seoul.csv`
  (초등학교 604 · 유치원 462 · 어린이집 459 · 학원·특수학교 등. 원본 `data_raw/zone/child_zone_std.csv`)
- 점 = 대상 시설 위치. 보호구역은 보통 정문에서 300m 안이라, **경로가 시설 200m 안을 지나면** 그 경로의 보호구역으로 봄
- 길안내에서는 시설에서 가장 가까운 경로 지점 ±200m 를 보호구역 구간으로 보고, 붙어 있는 구간은 하나로 합침
- 경로 카드: "🧒 어린이보호구역 근처 시설 4곳", 지도: 노란 원(반경 300m) + 🧒30
- 길안내 중: 300m 앞 음성 "300미터 앞, 어린이보호구역이에요. 시속 30킬로미터로 줄이세요.",
  구간 안에서는 노란 띠 "(30) 🧒 어린이보호구역 · 창서초등학교 외 2곳", 나가면 "어린이보호구역이 끝났어요."
- 제한속도는 표준데이터에 없어서 30km/h 로 둠 (대부분의 어린이보호구역 기준)

### 제한속도 표지판
- 보이는 순서: 단속카메라(500m 안) → 어린이보호구역(30) → **지금 달리는 도로 구간의 제한속도**
- 도로 제한속도: 표준노드링크(MOCT_LINK) 구간별 `MAX_SPD` → `web/data/road_links_seoul.csv` (22MB, **DVC** — `dvc pull` 로 받음)
  (다시 만드는 코드 `python web/make_road_limits.py data/service/moct/MOCT_LINK.shp`, pyshp 필요)
- 경로를 20m 마다 보고, 15m 안·같은 방향인 가장 가까운 도로 구간 값을 씀. 60m 안 되는 짧은 값은 무시(깜빡임 방지)
- 이 표가 없으면 예전처럼 500m 칸 안 도로들의 평균 제한속도를 씀 (골목 때문에 큰길에서도 30이 나올 수 있음)

## 3. 인터넷에 배포하기 (가이드)

### 가장 쉬운 방법: 발표 때만 잠깐 공개 (ngrok / Cloudflare Tunnel)
노트북에서 `python web/app.py` 를 켜 둔 채로, 터널 프로그램이 `https://xxxx.ngrok-free.app` 같은 주소를 만들어 줘요.
```bash
ngrok http 5000
```
- https 라서 휴대폰에서 **GPS(내 위치)도 동작**해요.
- 생긴 주소를 카카오 JavaScript SDK 도메인에 추가 등록해야 지도가 떠요 (주소가 바뀌면 다시 등록).
- 노트북을 끄면 사이트도 꺼져요.

### 계속 켜 두기: 클라우드 서버 (Render, Railway, PythonAnywhere 등)
1. 저장소에 `requirements.txt` 추가: `flask lightgbm pandas numpy requests pyproj gunicorn`
2. 시작 명령: `gunicorn -w 1 -b 0.0.0.0:$PORT --timeout 120 --chdir web app:app`
   (첫 실시간 계산이 20초 넘게 걸려서 timeout 을 늘려 둠. 워커 1개 = 메모리 절약)
3. **키는 `.env` 대신 서비스의 환경변수(Environment Variables) 화면에** 5개 입력
   (`app.py` 는 환경변수를 먼저 읽고 없으면 `.env` 를 읽음)
4. 모델·표 파일: `model/results/models/`, `data/service_tables/` 는 DVC 라 git에 없어요.
   배포용으로 이 두 폴더만 따로 올리거나(용량 약 35MB), 배포 시작 때 `dvc pull` 하도록 설정.
5. 배포 주소(`https://내앱.onrender.com`)를 카카오 JavaScript SDK 도메인에 등록.
6. 무료 요금제는 접속이 없으면 잠들어서 첫 접속이 느릴 수 있어요. 메모리 512MB 안팎이면 충분해요.

### 배포 전 확인
- 카카오맵·길찾기·서울시 API 하루 사용량 한도 (공개하면 여러 사람이 써서 금방 찰 수 있어요)
- 키가 담긴 `.env` 는 절대 git에 올리지 않기 (`.gitignore` 에 있음)
- 한글 파일 이름(`사고위험_모델.txt`)은 리눅스 서버에선 문제없지만, `app.py` 에 Windows 우회 코드가 있어서 그대로 써도 돼요.
